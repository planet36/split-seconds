# split-seconds

This repo holds the same small program written several ways, to compare speed, memory use, and output.  Each implementation reads one number of seconds per line from stdin and prints it split into days, hours, minutes, and seconds.

```console
$ printf '90061.5\n59.9996\n0.25\n1020.5\n0\n' | ./split-seconds-c
1d 1h 1m 2s
1m
0.250s
17m
0.000s
```

## Implementations

The implementations share no code.

| Name | Language | Formats the seconds with |
|---|---|---|
| `awk` | gawk | `sprintf` |
| `c` | C | `snprintf` |
| `decimal-py`, `decimal-pypy` | Python, PyPy | `decimal.Decimal` and an f-string |
| `FMT` | C++ | `fmt::format` |
| `FMT_INT` | C++ | `fmt::format`, plus `fmt::format_int` for the whole units |
| `google` | C++ | `double-conversion` |
| `java` | Java | `BigDecimal` |
| `oss` | C++ | `std::ostringstream` |
| `perl` | Perl | `sprintf` |
| `py`, `pypy` | Python, PyPy | an f-string |
| `to_s` | C++ | `f_to_s.hpp` and `i_to_s.hpp` |

## Requirements

The build needs these tools and libraries:

- A C compiler with C23 and a C++ compiler with C++23, such as GCC
- `libfmt` and `double-conversion`
- gawk, Perl, Python 3, and PyPy 3
- A JDK with `java.lang.IO` (25 or later)
- GNU `time` at `/usr/bin/time`, and GNU `make` and `bash`

The Makefile doesn't set a language standard, so it comes from the environment:

```bash
export CFLAGS=-std=gnu2y
export CXXFLAGS=-std=gnu++26
```

## Usage

```bash
make                # build all binaries and generate the input file
make bench          # time every implementation, then print md5sums of the outputs
make check          # check how every implementation handles valid and invalid input lines
make clean-output   # delete outputs, required to re-run implementations whose sources are unchanged
make clean          # delete binaries, input, and outputs
make bench TMP_DIR=/some/dir   # put the input and output files elsewhere
```

`make bench` reads sorted, unique values generated by `create-input-file.bash`.

## Results

`results.txt` is a log of a full `make bench` run, with the elapsed time and peak memory of each implementation.  Each figure comes from a single run on one machine.

The md5sums should form two groups, and `make bench` doesn't check this for you.  The `decimal` implementations parse the input text exactly, so ties land differently, as with `0.00050`, which gives `0.000s` instead of `0.001s`.  The others all use binary doubles and agree with each other.

## Input and output

- A valid line is a decimal number with an optional exponent, from 0 to 2^53 inclusive.  Whitespace around it is allowed, and a blank line prints an empty line.
- Anything else stops the run with an `Error:` message and exit status 1.
- Precision comes from the total value: 3 decimals below 10, 2 below 100, 1 below 1000, and otherwise 0.
- Zero units are omitted, unless nothing else would print, which gives `0.000s`.
- Seconds that round up to 60 carry into the larger units, so `59.9996` prints `1m`.
